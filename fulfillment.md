# Manual-First Fulfillment SOP

## Before access is granted

Get a written authorization that names:

- the business and authorized contact;
- which inbox, calendar, phone, CRM, or spreadsheet may be accessed;
- allowed hours and service area;
- approved customer-facing wording;
- escalation contact and emergency rules;
- data retention and deletion expectations;
- tools the client will pay for directly.

Never ask the client to send passwords or API keys in chat. Use the vendor's invite/role system or a secure transfer method they control.

## Day 0 — baseline

Create a client-owned or client-approved tracker with:

- timestamp
- source
- caller/customer name
- contact method
- job type
- service area
- urgency
- response time
- status
- booked time
- handoff reason
- final outcome when available

Record the baseline window before changing the process.

## Day 1 — approved script

Draft a short response that:

1. identifies the business and reason for contacting;
2. asks for only the minimum information needed;
3. does not diagnose, quote, or promise availability beyond approved rules;
4. offers a callback/booking path;
5. escalates emergencies or uncertainty to a human.

The client approves the final language.

## Day 2 — run manually

For every lead, log the event and use the approved workflow. Human-review every customer-facing message until the client approves a narrower automation boundary.

## Daily report

Send:

- new leads
- missed/unresolved leads
- median/average response time
- qualified conversations
- appointments booked
- exceptions and escalations
- one recommended improvement

Do not report fabricated ROI. If closed revenue is unavailable, say so.

## Weekly review

Ask:

- Which lead sources produce qualified work?
- Which questions create drop-off?
- Which exclusions are unclear?
- What was handed off and why?
- Is the client receiving enough value to renew?

## When to pause

Pause the workflow and notify the client for:

- safety or medical emergencies;
- threats, harassment, or legal complaints;
- requests involving sensitive personal data beyond the agreed scope;
- wrong numbers or suspected fraud;
- conflicting client instructions;
- any error that could create a customer promise the business did not approve.

## Client handoff checklist

- [ ] Signed scope/order form
- [ ] Payment received or agreed milestone
- [ ] Authorized access path
- [ ] Business hours and service area
- [ ] Job types and exclusions
- [ ] Emergency escalation rules
- [ ] Booking calendar rules
- [ ] Approved scripts
- [ ] Tracker created
- [ ] Baseline captured
- [ ] Reporting cadence set
